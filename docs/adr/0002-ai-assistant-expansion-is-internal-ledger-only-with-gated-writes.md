# The AI assistant expansion stays internal-ledger-only, with dual-Active-Provider tool-calling and gated writes through Pending Actions, Memory Entries, and Audit Log Entries

The AI assistant is growing from a context-only chat feature into something that can call tools and, eventually, touch the ledger — this phase's planned additions are tool-calling (shared across both LLM Providers), AI-proposed transactions, persistent AI memory, and a full audit trail. We're scoping this expansion to the internal ledger this app already owns: the assistant can read and reason over the portfolio/transactions/positions data and call research tools against data this app already fetches (news, and later quotes and options chains), but it does not talk to a brokerage, does not execute trades, does not search the live web, and does not run on a schedule or act proactively in the background — every tool call and every proposed write happens inside a user-initiated chat turn. We picked this boundary because the ledger is a tracker, not a trading or research platform, and because scoping the assistant to data and actions this app already mediates keeps every tool call auditable and every side effect reversible, without taking on brokerage API integration, outbound web-search infrastructure, or a job scheduler before the simpler in-turn version has proven out. Tool-calling itself is built once, not per Active Provider: a shared `tools` field on the neutral `LlmChatRequest` (consumed by both `anthropic.ts` and `ollama.ts`) lets a capped agentic loop in the chat route call tools regardless of whether `anthropic` or `ollama-cloud` is active, so the assistant's capabilities don't fork by provider the way the extended-thinking `thinking` param already does per ADR-0001; Positions and the client-side Watchlist are still auto-injected as plain context rather than exposed as tools, since they're cheap, already fetched per turn, and don't benefit from being model-invoked. For anything that would change the ledger or persist across turns, we rejected letting the model write directly: a proposed transaction becomes a Pending Action that a human must confirm or reject before anything is written, and an AI-written note becomes a Memory Entry — a distilled, model-authored note, never a raw tool-result dump — that the user can only delete, not edit in place, trading editability for a simpler and harder-to-corrupt correction path. Every chat transcript, tool call, Pending Action lifecycle event, and Memory Entry write is recorded as an immutable Audit Log Entry with no update or delete path, so the assistant's expanding autonomy is paired with a complete, tamper-proof record of what it did and why, rather than deferring auditability until trust issues force the question.

**Consequence**: several adjacent features are explicitly deferred rather than rolled into this phase — brokerage integration and trade execution, live web search, scheduled or proactive background research, multi-user support, an editable (vs. delete-only) Memory UI, and non-standard options multipliers (the ledger's option positions use a fixed 100x contract multiplier; see `OPTION_CONTRACT_MULTIPLIER` in `server/src/routes/portfolio.ts`). Each is a real expansion of scope — a new integration, a new trust boundary, or new UI — and is tracked as separate future work rather than assumed here.
